2. State Management — StatefulWidget (`setState`)

Ephemeral / Local Component State

Topic 1
📝 Scenario Question Asked by Professor
"Develop a Flutter screen where a user clicks an increment/decrement button to update a counter or toggle status, and the screen re-renders immediately to reflect the updated value without reloading the application."
✔
State variable declared inside _CounterScreenState
✔
`setState(() { _counter++; })` triggers the rebuild
✔
Button connects directly to the method
dart • Solution for StatefulWidget Scenario 
import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: CounterScreen()));

class CounterScreen extends StatefulWidget {
  const CounterScreen({super.key});

  @override
  State<CounterScreen> createState() => _CounterScreenState();
}

class _CounterScreenState extends State<CounterScreen> {
  // 1. State Variable
  int _counter = 0;

  // 2. Mutation Logic with setState()
  void _increment() {
    setState(() {
      _counter++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('StatefulWidget Counter')),
      body: Center(
        child: Text(
          'Count: $_counter',
          style: const TextStyle(fontSize: 32, fontWeight: FontWeight.bold),
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _increment,
        child: const Icon(Icons.add),
      ),
    );
  }
}

3. State Management — Provider (`ChangeNotifier`)

App-Wide Decoupled State Architecture

Topic 2
📝 Scenario Question Asked by Professor
"A shopping cart or counter state must be shared across the entire app. To avoid rebuilding the entire screen and separate business logic from the UI, implement state management using the Provider package with `ChangeNotifier`, `ChangeNotifierProvider`, and `Consumer`."
1
Step 1: Model class extends ChangeNotifier + calls notifyListeners()
2
Step 2: Wrap root widget inside ChangeNotifierProvider(create: ...)
3
Step 3: Read state with Consumer<T> and call with Provider.of(..., listen:false)
dart • Solution for Provider Scenario (3 Steps) 
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

// ==============================================================
// STEP 1: Provider / Model Layer (extends ChangeNotifier)
// ==============================================================
class CounterProvider extends ChangeNotifier {
  int _count = 0;
  int get count => _count;

  void increment() {
    _count++;
    notifyListeners(); // ⭐ Tells all Consumer widgets to rebuild
  }
}

// ==============================================================
// STEP 2: Wrap Application Root in main()
// ==============================================================
void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => CounterProvider(),
      child: const MaterialApp(home: ProviderScreen()),
    ),
  );
}

// ==============================================================
// STEP 3: UI Layer (StatelessWidget + Consumer)
// ==============================================================
class ProviderScreen extends StatelessWidget {
  const ProviderScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Provider State')),
      body: Center(
        // Consumer rebuilds ONLY this specific Text child
        child: Consumer<CounterProvider>(
          builder: (context, provider, child) {
            return Text(
              'Count: ${provider.count}',
              style: const TextStyle(fontSize: 32, fontWeight: FontWeight.bold),
            );
          },
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          Provider.of<CounterProvider>(context, listen: false).increment();
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
Comparison Factor setState (StatefulWidget) Provider (ChangeNotifier)
Scope Local / Ephemeral (Single Screen) Global / App-wide (Multi-Screen)
Rebuild Behavior Rebuilds entire build() method Rebuilds only the subscribed Consumer
Architecture Couples UI with state logic Decouples Business Logic from Presentation

4. Local Data Persistence — SharedPreferences

Key-Value Persistent Disk Storage

Topic 3
📝 Scenario Question Asked by Professor
"Create a User Login Session / Profile screen with 'Remember Me' or local username storage. When the user enters their name and hits Save, store it locally using SharedPreferences. When the application restarts, automatically restore and display the saved name. Provide a Clear / Logout button."
✔
`SharedPreferences.getInstance()` is asynchronous (needs await)
✔
`prefs.setString('key', val)` writes to disk
✔
`prefs.getString('key') ?? default` reads safely
✔
`prefs.remove('key')` clears the session
dart • Solution for SharedPreferences Session Scenario 
import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() => runApp(const MaterialApp(home: LoginSessionScreen()));

class LoginSessionScreen extends StatefulWidget {
  const LoginSessionScreen({super.key});

  @override
  State<LoginSessionScreen> createState() => _LoginSessionScreenState();
}

class _LoginSessionScreenState extends State<LoginSessionScreen> {
  final TextEditingController _nameController = TextEditingController();
  String _savedName = 'No user logged in';

  @override
  void initState() {
    super.initState();
    _loadData(); // Load saved preference on startup
  }

  // 1. READ DATA (Async)
  Future<void> _loadData() async {
    final prefs = await SharedPreferences.getInstance();
    setState(() {
      _savedName = prefs.getString('username') ?? 'No user logged in';
    });
  }

  // 2. WRITE DATA (Async)
  Future<void> _saveData() async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString('username', _nameController.text);
    _loadData(); // Refresh UI
  }

  // 3. CLEAR DATA (Logout)
  Future<void> _clearData() async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.remove('username');
    _loadData(); // Refresh UI
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('SharedPreferences Session')),
      body: Padding(
        padding: const EdgeInsets.all(16.0),
        child: Column(
          children: [
            TextField(
              controller: _nameController,
              decoration: const InputDecoration(labelText: 'Enter Username'),
            ),
            const SizedBox(height: 12),
            Row(
              mainAxisAlignment: MainAxisAlignment.spaceEvenly,
              children: [
                ElevatedButton(onPressed: _saveData, child: const Text('Save / Login')),
                ElevatedButton(onPressed: _clearData, child: const Text('Clear / Logout')),
              ],
            ),
            const SizedBox(height: 20),
            Text('Saved User: $_savedName', style: const TextStyle(fontSize: 18)),
          ],
        ),
      ),
    );
  }
}

5. Local Relational Database — SQFLite (Full CRUD)

Relational SQLite Database with Singleton Pattern

Topic 4
📝 Scenario Question Asked by Professor
"Write a complete Flutter DatabaseHelper class using SQFLite for a Student entity (id, name, rollNo). Implement the four CRUD operations: Create (Insert), Read (Query All), Update, and Delete. Show how to initialize and invoke it."
✔
Singleton instance: DatabaseHelper._init() & static Database? _database;
✔
`openDatabase` with path & onCreate: _createDB
✔
[C] Insert: db.insert('students', row)
✔
[R] Read: db.query('students')
✔
[U] Update: db.update(..., where: 'id = ?', whereArgs: [id])
✔
[D] Delete: db.delete(..., where: 'id = ?', whereArgs: [id])
dart • Standard DatabaseHelper Class (Paper Exam Champion) 
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

class DatabaseHelper {
  // 1. Singleton pattern
  static final DatabaseHelper instance = DatabaseHelper._init();
  static Database? _database;

  DatabaseHelper._init();

  Future<Database> get database async {
    if (_database != null) return _database!;
    _database = await _initDB('student.db');
    return _database!;
  }

  // 2. Open / Create Database File
  Future<Database> _initDB(String filePath) async {
    final dbPath = await getDatabasesPath();
    final path = join(dbPath, filePath);

    return await openDatabase(
      path,
      version: 1,
      onCreate: _createDB,
    );
  }

  // 3. Create Table SQL
  Future _createDB(Database db, int version) async {
    await db.execute('''
      CREATE TABLE students (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT NOT NULL,
        rollNo TEXT NOT NULL
      )
    ''');
  }

  // ==============================================================
  // 4. CRUD OPERATIONS (The Core Answer on Paper!)
  // ==============================================================

  // [C] CREATE / INSERT
  Future<int> insertStudent(Map<String, dynamic> row) async {
    final db = await database;
    return await db.insert('students', row);
  }

  // [R] READ / QUERY ALL
  Future<List<Map<String, dynamic>>> queryAllStudents() async {
    final db = await database;
    return await db.query('students');
  }

  // [U] UPDATE
  Future<int> updateStudent(Map<String, dynamic> row) async {
    final db = await database;
    int id = row['id'];
    return await db.update('students', row, where: 'id = ?', whereArgs: [id]);
  }

  // [D] DELETE
  Future<int> deleteStudent(int id) async {
    final db = await database;
    return await db.delete('students', where: 'id = ?', whereArgs: [id]);
  }
}
dart • How to Call CRUD from Flutter UI 
// 1. Insert record
await DatabaseHelper.instance.insertStudent({
  'name': 'Maaz Ali',
  'rollNo': '3143',
});

// 2. Query all records
List<Map<String, dynamic>> students = await DatabaseHelper.instance.queryAllStudents();

// 3. Delete by ID
await DatabaseHelper.instance.deleteStudent(1);
